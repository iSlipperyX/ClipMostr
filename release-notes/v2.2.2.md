ClipMonster 2.2.2 makes updating reliable.

## Fixed
- **Updates that didn't complete.** The updater used to rename the whole ClipMonster folder, which Windows refuses while anything has the folder open: a File Explorer window, a terminal, or a program started from inside it. It now replaces the app's own files in place, one by one when a folder is held open, so these no longer stop an update.
- **Your files in the ClipMonster folder.** From 2.2.2 on, updates leave anything you keep in the folder besides the app itself alone. Before, an update replaced the whole folder.
- **Safer restore.** If a file can't be replaced, everything goes back exactly as it was. If something can't be put back, the updater leaves a note listing exactly what to move, and never asks you to delete anything.
- **Background automation.** An update now waits for automation to pause. If it doesn't, the update tells you to stop it on the Automation tab, where before it only said a process was in the way.
- **Clearer messages.** When an update doesn't complete, ClipMonster now says why. If you open it while an update is still installing, it asks you to close it for a minute, where before it reported a failure. `ytclip --update` also works from a terminal inside the ClipMonster folder now.

## Updating
2.2.1's updater installs this update, so it replaces the whole ClipMonster folder one last time. Before updating, close any File Explorer windows and terminals on the folder, and copy out anything of your own you keep in it. Updates after this one don't need that.
