ClipMonster 2.4.1 fixes Windows Defender removing ClipMonster, and automation looking stopped while it was busy.

## Fixed
- **Windows Defender no longer has reasons to remove ClipMonster.** On one PC, Defender's behaviour check (`Behavior:Win32/Execution.A!ml`) quarantined ClipMonster.exe while automation was running. It also deleted the Start with Windows task. ClipMonster now avoids what that check looks for:
  - Updates install through ClipMonster's own `ytclip.exe` instead of a hidden PowerShell script started with `-ExecutionPolicy Bypass`.
  - Start with Windows uses the usual startup entry (the one in Task Manager → Startup apps) instead of a scheduled task.
  - Checking for other open ClipMonster windows before an update no longer starts PowerShell.
- **Automation no longer looks stopped while it's working.** During a long step, such as Whisper typing out a long video, the Automation tab could say "Not running" for minutes. Automation now reports that it's alive every 5 seconds, whatever it's doing.
- **Only one automation at a time.** Pressing Start while automation was busy and quiet could start a second one on the same video, which made both run at half speed. Now a second one won't start while the first is still running. If the first really is stuck, the Automation tab says so and tells you to end it in Task Manager.
- **AI calls that stall give up sooner.** A clip-finder or polish call that stops receiving data now retries after 2 minutes instead of 10.

## New
- **Where the time went.** Each finished video gets a log line such as "took 6:05 (download 1:10, transcript 2:40, AI polish 40 s, export 1:05)".
- **Old update downloads are removed.** Each update left a 225 MB zip in `%LOCALAPPDATA%\ClipMonster\updates`, and the unpacked copy next to the app folder. Both are now removed once an update succeeds. On a PC that has been updating since 2.0.0, that frees about 2 GB.
- **A warning if ClipMonster is inside OneDrive.** The health check says when the app folder is inside OneDrive, for example a Desktop that OneDrive backs up. Syncing slows updates, and a program that changes its own files inside a synced folder is one more thing Defender's check reacts to. Move the whole ClipMonster folder to `C:\Users\<you>\ClipMonster` and open it from there.

## Tidier log
- A YouTube sign-in request is quoted once, not twice in full.
- "Using the Research tab's last check" appears only when that check picks something, not every half hour.

## If Defender already removed ClipMonster
1. Open Windows Security → Virus & threat protection → Protection history.
2. Find ClipMonster.exe and choose **Actions → Restore**.
3. Open ClipMonster, install this update, and turn **Start with Windows** back on in the Automation tab.

## Updating
Installed copies offer this update automatically. This last update still installs the old way. Updates after it use the new installer.
